# Project lifecycle

For a requested scope update, preserve supplied wording and create a `project-update` proposal with a rationale and optional reassessment note. Preview the brief diff with `research_catalog_preview`. Offer link reassessment afterward; do not unlink as a side effect.

During reassessment, separate kept, newly proposed, and questionable links. Tie each to the current brief and represent removals as durable proposals with reasons.

For explicit archival, create a `project-archive` proposal with both rationale and reassessment, then preview the status change and effect on discovery with `research_catalog_preview`. Archival does not delete the note or remove links unless separately requested.

If the user rejects any catalog lifecycle proposal, direct them to `research catalog reject <proposal-id>`. This records the rejection and clears the pending mirror without applying the proposed project changes.
