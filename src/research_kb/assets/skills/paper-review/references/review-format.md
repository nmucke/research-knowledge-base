# Compact review format

Pass the complete Markdown below as `managed_review`. Replace every placeholder, retain every heading and provenance label, and use `none` when a tag category is empty.

```markdown
> **Generated by:** <agent>
> **Model:** <model identifier, or a truthful unavailable marker>
> **Date:** <YYYY-MM-DD>
> **Scope:** <abstract-only | partial-text | full-text>
> **Coverage:** <complete | partial | unknown>
> **Human verified:** No

### Summary

- <one to three evidence-bounded bullets>

### Main contribution

<one or two sentences>

### Main limitations

- <one or two limitations>

### Reading recommendation

**<Must read | Read | Skim | Skip | Uncertain>.** <reason grounded in the reading profile>

### Tags

**Suggested existing tags:** `<registry tags, or none>`
**Suggested new tags:** `<new tags, or none>`
```

When projects were considered, append:

```markdown
### Projects

**Relevant:** `<project identifiers, or none>`
**Considered:** `<rejected identifiers with brief reasons, or none>`
```

## Structured field mapping

- Copy the review session's `session_id`, `citekey`, and `expected_revision` unchanged.
- `agent`, `model`, `review_date`, `review_scope`, and `review_coverage` must match the provenance lines. Use the actual context scope; never upgrade it.
- Map the recommendation to `must-read`, `read`, `skim`, `skip`, or `uncertain`; put its explanation in `recommendation_reason` and set a supported confidence.
- Put proposed registry tags in `applied_tags`. Despite the stored compatibility name, these are only suggested existing tags until the user decides.
- Put genuinely new tags in `suggested_tags`, with exactly one nonblank entry per tag in `suggested_tag_definitions`.
- Put relevant project identifiers in `suggested_projects`. Set `suggested_project_rationales` to exactly those identifiers, with each value naming the project goal or scope statement the paper bears on. Submission proposes links; it does not approve them.
- Keep tags unique and within the skill limits. The Markdown labels and structured lists must describe the same choices.

Copy the scope returned by the session: `abstract-only` for abstract evidence, `partial-text` for incomplete extraction, or `full-text` for complete extracted text. Scope describes the available source; coverage describes what you actually inspected. Keep the session scope and set coverage to `partial` or `unknown` if you did not inspect material pages or could not verify important visual evidence. Never imply that full-text extraction means figures were visually inspected. `complete` means the requested evidence scope was fully covered.
