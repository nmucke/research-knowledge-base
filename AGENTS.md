# Literature management instructions

This repository is an Obsidian literature vault connected to Zotero. Zotero owns bibliographic metadata and PDFs; the user alone owns human reading state and notes.

## Review workflow

For a request to review `<citekey>`:

1. Run `research review-context <citekey>`.
2. Read all four files reported by the command: the paper note, extracted paper text, `System/reading-profile.md`, and `System/tag-registry.md`.
3. Edit only AI-owned frontmatter fields and the content between `<!-- BEGIN MANAGED:AI_REVIEW -->` and `<!-- END MANAGED:AI_REVIEW -->`.
4. Run `research validate <citekey>` and correct only AI-owned content until it passes.

## Review contract

- Target 120–180 words of review prose and keep it below 200 words unless the user explicitly requests otherwise. Metadata and tags do not count toward this limit.
- Use at most three summary bullets, state the main contribution in one or two sentences, give one or two important limitations, and include a reading recommendation with a concise reason based on the reading profile.
- Select at most five existing registry tags into `ai_applied_tags`. Put at most two genuinely new proposals in `ai_suggested_tags`.
- Record the actual agent, model when available, date, review scope, and extraction coverage in frontmatter and in the managed review block. State incomplete or poor extraction plainly.
- Keep claims within the available evidence. An abstract-only review cannot support details from the body; use `full-text` only when the full extracted text is available. Never invent page references.
- Keep `ai_review_human_verified: false`. AI output is never human-verified; only the user may change that field.

## Required managed-block format

Replace the managed AI-review placeholder with this structure, using truthful values and concise prose:

```markdown
> **Generated by:** <agent>
> **Model:** <model identifier, if available>
> **Date:** <review date>
> **Scope:** <actual review scope>
> **Coverage:** <actual extraction coverage>
> **Human verified:** No

### Summary

- <up to three summary bullets>

### Main contribution

<one or two concise sentences>

### Main limitations

- <one or two important limitations>

### Reading recommendation

**<Recommendation>.** <Concise reason based on the reading profile.>

### Tags

**Applied:** `<up to five existing registry tags>`
**Suggested:** `<up to two proposed new tags>`
```

## Protected content

- Never change `human_read_status`, `human_read_date`, `human_rating`, `human_priority`, or `human_relevance`.
- Never write inside `## Human notes`, or alter Zotero-owned, Better-BibTeX-owned, shared curated, or unmanaged content.
- Never promote suggested tags into `tags`, edit the tag registry to approve them, or push tags to Zotero as part of a review. Those require a separate explicit user action.
- Never repair validation failures by changing protected content.
